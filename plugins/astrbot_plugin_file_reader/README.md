# 文件阅读

她收到文件时，自动读内容再回答。短文件全文进对话，长文件分段读完整理成笔记。

## 支持的格式

| 类型 | 后缀 |
|---|---|
| PDF / EPUB | `.pdf` `.epub` |
| Word | `.docx` |
| Excel | `.xlsx` `.xlsm` `.xls`（旧版） |
| PPT | `.pptx` |
| 网页 | `.html` `.htm`（先剥掉 `head`/`script`/`style`，只留正文） |
| 文本 / 代码 | `.txt` `.md` `.csv` `.json` `.yaml` `.xml` `.py` `.js` 等 |

图片不走这里（走 AstrBot 的图片描述）；`.doc`/`.ppt` 老格式读不了。

## 两条路径

**短文件（正文 ≤ 30000 字）**：全文直接拼进这一轮 prompt，她立刻能答。

**长文件（正文 > 30000 字）**：

1. 先回一句「文件有点长（N 字），我分段读一下，稍等…」；
2. 按行切段（每段约 12000 字，相邻重叠 400 字，尽量不把一句话劈开）；
3. 每段交给模型提炼要点（默认用她的聊天模型 `deepseek-v4-pro`，关掉思考模式；2 万字约 10 秒）；
4. 把各段要点再合成一份笔记：时间线 + 人物关系变化 + 值得记住的约定/事实；
5. 笔记拼进这一轮，同时保留原文索引，她可以用 `search_file` 按关键词回查原句。

实测：2.1 万字 → 2 段 / 3 次调用 / 9.8 秒（v4-pro），笔记 714 字。

## 限制

- 最多读 40 段（约 48 万字），超出的部分会明说「后面没读」；
- 笔记是有损压缩：能保住时间线、人物、约定和事实，保不住每句话——细节靠 `search_file`；
- 单张 Excel 表最多看 500 行；
- 解析失败只写日志（`astrbot.log` 搜 `[file_reader]`），不影响正常聊天。

## 配置

| 项 | 默认 | 说明 |
|---|---|---|
| `enabled` | true | 总开关 |
| `small_limit` | 30000 | 正文超过这个字数就改走分段读 |
| `max_chars` | 30000 | 短文件直接注入时的字数上限 |
| `max_chunks` | 40 | 长文件最多读多少段 |
| `ttl_seconds` | 300 | 读好的内容多久内会拼进下一轮 |
| `session_ttl_seconds` | 1800 | 笔记和索引保留多久（这段时间内能追问） |

## 追问

读完的 30 分钟内，`search_file("关键词")` 会在**原文**里找命中行（带行号和上下文），
所以「他 7 月 12 号那天说了啥」这种细节问题可以回查，不用重发文件。
